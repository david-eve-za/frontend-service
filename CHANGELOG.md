# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Elsione per-folder completion flags with resumable sync passes**: every novel folder listed completely in a pass is flagged (`Novel.listingComplete` + `lastListedAt`); the next runs SKIP those folders (one preload query per run, O(1) lookups in the walk — a saved HTTP listing + anti-ban pause per folder) and only list the pending ones, the always-cheap category folders and the root. A cancelled run resumes exactly where it stopped, and skipped folders still count as visited so their volumes are not marked removed. When 100% of the folders are flagged (local catalog mirrors the server), the next run resets every flag with one bulk update and starts a full cycle again. The sync status exposes the cycle (`fullCycle`, `foldersComplete`, `foldersPending`, `skippedFolders`) and every milestone is logged ("Pasada incremental: 79/1343 carpetas completas…", per-folder skips, per-novel upsert detail).
- **Multi-class log filtering**: the live viewer's class filter became a multi-select (several classes at once, with counts), and `GET /api/logs/search` accepts a comma-separated `loggers` parameter (typed IN predicate — an untyped `root.get(...)` silently matches nothing in Hibernate 6).
- **Exhaustive backend logging, fully javadoc'd**: milestone INFO logs for `saveBlocks` (blocks + rebuilt clean-text size), both split variants (chunks per block / whole text), `deleteBook` (rows removed per table), the translation dispatch (pending chunks) and the audio synthesis (chars, fragments, target) — completing the pipeline coverage (step transitions, per-chunk translations, catalog sync) so every operational flow is now traceable in the live viewer and the persisted history.

### Fixed

- **`ddl-auto: update` could not add the flags columns to the existing `novel` table** (NOT NULL on 1,347 populated rows without a DEFAULT is silently skipped by hbm2ddl): the idempotent `DatabaseIndexInitializer` now also guarantees column additions (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS ... DEFAULT FALSE NOT NULL`), backfilling existing rows at startup.
- **Scope-reactive Traducir Libro page with per-chunk translation**:
  - The parallel original/translation view is now scope-aware: "Libro completo" shows every chunk in deterministic reading order (block position, then chunk position within it) instead of the previous unsorted page, and each chunk is badged with its owning Prólogo/Capítulo/Epílogo block (the long-pending block badge of the block-scoped design); "Bloques específicos" lists the marked blocks progressively (chips panel) and filters the chunk view live to the marked blocks as they are checked.
  - New per-chunk "Traducir chunk" action: `POST /api/files/{bookId}/chunks/{chunkId}/translate` validates book, chunk ownership and text, reuses the book glossary and dispatches through `ChunkTranslationService` (own virtual thread, shared 30 RPM quota, short transactions — the pipeline's exact dispatch path). A COMPLETED chunk can be re-translated and nothing else is touched; 409 while a pipeline pass runs. The UI polls per chunk (2.5 s up to 60 s) with a per-chunk spinner.
  - `GET /api/files/{bookId}/chunks` accepts an optional comma-separated `blocks` parameter (scope-filtered view) and returns block metadata per chunk through the new LOB-free `ChunksRepository.ChunkView` projection (LEFT JOIN — block id/type/number reach the UI without loading the block content CLOB).
- **Traceable chunk translations and a noise filter in the live log viewer**: `ChunkTranslationService` now logs the full per-chunk lifecycle ("Traduciendo chunk X (N caracteres)" / "Chunk X traducido (A → B caracteres, D ms)") with the pipeline MDC keys (bookId / traceId=chunkId / step=TRANSLATE) filled inside the async worker — manual single-chunk requests and every chunk of a full run are now visible and filterable in the live viewer (previously nothing but errors appeared). The request itself is audited ("Traducción individual solicitada: chunk X del libro Y (N caracteres, estado previo: S)"). The viewer gains an "Excluir (clase o texto)" filter, defaulted to `NovelsCatalogSync`, so the elscione batch lines stop burying the pipeline events. Manual single-chunk translations deliberately do NOT write `ProcessTraceEvent` rows (they would consume the TRANSLATE retry budget).
- **Database log history with 7-day retention**: Logback events (from `app.log-persistence.min-level`, default INFO — DEBUG stays live-only) persist to the new `log_event` table for post-mortem analysis. A second root-logger appender (`LogEventDbAppender`, attached at `ApplicationReady` like the stream one) feeds a bounded in-memory queue (20k, drop-on-overflow with a rate-limited warn — logging never blocks); a self-managed virtual-thread scheduler flushes batches of up to 1000 rows every 5 s with a single `saveAll` (a DB failure re-enqueues the transactional batch and retries — no losses, no duplicates; a final flush runs on shutdown), and a purge at startup plus daily bulk-deletes everything older than `app.log-persistence.retention-days` (default 7). The pipeline MDC is stored as first-class columns (`book_id`, `trace_id`, `step`) with `(logged_at)`, `(book_id, logged_at)` and `(level, logged_at)` indexes; messages are truncated to 8000 chars in a searchable VARCHAR. Analysis endpoint: `GET /api/logs/search?from=&to=&level=&bookId=&q=&page=&size=` (JPA Specification filters, newest first) returns the viewer's `LogEventDto` shape.

- **Database optimization pass (queries, indexes, caches)**:
  - **Query-driven composite indexes**, declared on the entities and guaranteed on the long-lived H2 file by the new `DatabaseIndexInitializer` (idempotent `CREATE INDEX IF NOT EXISTS` + `ANALYZE` on startup): `novel(title)`, `blocks(book_id, position)`, `chunks(book_id, status)`, `chunks(block_id, position)` and `process_trace_event(book_id, step, started_at)` — each annotated with the query pattern it serves.
  - **Caffeine cache layer** (`CacheConfig` + `spring.cache`): `regexPatterns` (cleaning patterns read on every text extraction, evicted by the pattern CRUD) and `catalogCounts` (dashboard novel/volume COUNTs, evicted whenever a catalog sync run finishes), replacing the hand-rolled racy 60-second TTL pattern cache in `TextExtractorService`.
  - **`OptimizedQueriesTest`**: a `@DataJpaTest` integration suite (11 tests) that exercises every new projection, bulk update and bulk delete against real H2 and asserts the composite indexes exist in the schema.
- **Shared NVIDIA rate limiter** (`NvidiaRateLimiter`, `app.nvidia.rate-limit-rpm: 30`): token bucket with full initial capacity and one permit every `60/rpm` seconds; `acquire()` blocks (virtual threads park) until quota is free. Applied at both API chokepoints — every model attempt in `NvidiaAiService.callModelWithRotation` (including retries and key rotation) and glossary extraction in `GlossaryService` — so translation, retries and extraction share one orchestrated budget across the whole pipeline. `rpm <= 0` disables the limiter.
- **Configurable parallel TTS** (`app.audio.tts-concurrency: 3`): `AudioGeneratorService` synthesizes a block's internal ~1000-char TTS fragments concurrently toward the Edge TTS endpoint and merges them in order afterwards.
- **`ChunkTranslationService`**: dedicated bean for per-chunk translation, invoked through the Spring async proxy.

### Changed

- **Virtual-thread executor**: `bookProcessingExecutor` switches from a 4–8 platform-thread `ThreadPoolTaskExecutor` to `SimpleAsyncTaskExecutor` with `setVirtualThreads(true)` (Java 21). Pipeline tasks — orchestrator runs, chunk translations, audio — park for free during NVIDIA/Edge-TTS/LLM waits instead of pinning platform threads. The `MdcTaskDecorator` is preserved, so every log line still carries `bookId`/`traceId`/`step` for the Visor de Logs.
- **Truly parallel chunk translation**: every pending chunk translates on its own virtual thread with the glossary injected, paced by the shared limiter.
- **LOB-free pipeline reads**: `Book.fullText` (up to ~578 KB per book) used to ride along with every `findById` — orchestrator entry/steps, `startStep`/`skipStep` checkpoints, the `/list` and `/{id}/status` endpoints, startup recovery and the glossary FK link. All of those now read light projections (`findStatusViews`, `findBookListViews`, `hasExtractedText` via `LENGTH(TRIM(full_text))` in SQL) or move state with bulk updates (`updateCheckpoint`, `updateStatusWhen`, `updateStatusAndTrace`, per-block `updateAudioFilePath`); trace attempt counting is a single `COUNT` instead of loading every event, and the glossary links its Book FK via `getReferenceById`.
- **TRANSLATE step on light projections**: pending-chunk evaluation reads only (id, status, attempts); stale requeue, legacy attempt healing and post-failure accounting are single bulk UPDATEs; the dispatch list is an id-only query. Chunk texts are loaded solely by the translating virtual thread, and the per-block audio step loads all blocks' chunks in ONE query.
- **No DB transaction around LLM calls**: `translateChunk` and `processBookChunksAsync` no longer declare `@Transactional`, so no Hikari connection stays pinned during the NVIDIA API call (seconds to minutes at 30 RPM); each persistence step runs in its own short transaction. This removes the connection-pool saturation risk of the parallel chunk translation.
- **N+1 elimination in the novels manager**: one grouped volume-count query per catalog page (was one COUNT per novel), one grouped total/completed chunk-count query per page (was two COUNTs per volume), one `findByVolumeIdIn` for all files (was one query per volume) and batched book status views — no per-volume lazy `Book` load of the `full_text` CLOB anymore.
- **Batched catalog sync**: volumes and files accumulate and flush in one `saveAllAndFlush` per kind instead of one `saveAndFlush` round-trip per row; novels that disappear from the source are marked with a single bulk UPDATE instead of paging every novel and saving each volume.
- **JDBC batching + dirty-write hygiene**: `hibernate.jdbc.batch_size=25` with `order_inserts`/`order_updates`, `@DynamicUpdate` on hot entities, and `saveAll` for chunks/blocks/glossary terms (was one `save` per row). Derived `deleteAllBy*` became bulk `deleteBy*InBulk` JPQL deletes (no entity loading before delete), all `@Modifying` operations use `flushAutomatically`/`clearAutomatically` so the persistence context never serves stale rows.
- **Database/runtime tuning**: `spring.jpa.show-sql: false`, `spring.jpa.open-in-view: false`, and the H2 URL gains `CACHE_SIZE=65536` (64 MB page cache for the ~24 MB database, default was 16 MB).

### Fixed

- **The Dividir Texto editor could silently destroy a document**: `saveBlocks` rebuilds `full_text` solely from the marked blocks, so saving with zero, one or a few blocks marked discarded every unmarked paragraph forever — the balance validation only guaranteed matched tags. This is exactly how Volume 19 lost its 25 translated chunks. The editor now measures the text that would be discarded (mirroring the exact parse regex) and blocks the first Guardar with a warning that includes the character count; a second explicit click proceeds, so intentionally dropping short junk remains possible.
- **Two latent persistence bugs caught by the new log-history tests before shipping**: a pre-assigned `@GeneratedValue` id made `saveAll` treat new rows as detached entities and issue an UPDATE of a missing row (`ObjectOptimisticLockingFailure`), and Hibernate 6 silently ignores predicates added via `cb.conjunction().getExpressions().add(...)` (the generated SQL kept `where 1=1`, which would have disabled every `/api/logs/search` filter) — ids are generated on persist and specifications now combine filters with `cb.and(...)`.
- **Deep links and reloads on client routes returned a JSON 500**: `/pipeline/translate-book` (and `/logs`) are Angular client-side routes, but the SPA fallback in `WebConfig` only covered a hardcoded prefix list — a reload or bookmark on any pipeline route fell through to the static-resource handler and surfaced `NoResourceFoundException` as `{message: "An unexpected error occurred.", details: "No static resource pipeline/translate-book ..."}`. `GlobalExceptionHandler` now handles `NoResourceFoundException` explicitly: every non-API, non-asset path (no `/api`, `/api-docs`, `/swagger-ui`, `/h2-console`, `/error` prefix, no file extension) forwards to `index.html` so the Angular router boots into the right page; genuine misses (unknown API endpoints, broken asset links) get a proper 404 JSON instead of the generic 500. Verified live: `/pipeline/translate-book` and `/logs` serve the app shell (200), `/api/unknown` returns 404 JSON, and the catalog API keeps working.
- **Re-sync could drop volume metadata**: the batched upsert only persisted brand-new volumes, so the refresh of `label`, `translatorGroup` and the `removedFromSource` reset of existing rows relied on dirty checking and could be silently lost; every touched row is now persisted and flushed explicitly.
- **Sequential self-invocation defect**: `processBookChunksAsync` called `translateChunkAsync` via `this.`, bypassing the `@Async` proxy — so chunks translated sequentially despite the async annotations. Chunk translation now goes through the `ChunkTranslationService` proxy.

Measured on a two-chunk book: ~44s total with two interleaved virtual threads vs ~88s sequential. 78/78 tests green, including the new `NvidiaRateLimiter` and `ChunkTranslationService` suites. Database pass verified with 334/334 tests green (11 of them the new H2 integration suite); the SPA deep-link fix brings the suite to 340/340.

## Prior work

Summary of the project history before this changelog existed (no releases were tagged):

- **Setup & guides**: conductor setup, Google-inspired Java/Markdown style guides, Swagger, JUnit 5, dependabot, `.gitignore` for build artifacts.
- **Book Translator UI**: top-level menu and pages, sidebar navigation, 3-step upload wizard, blockML semantic block editor.
- **Regex pattern management**: CRUD for text-cleaning patterns (form v1, table + modal v2, infinite-loading fix).
- **Novels catalog & sync**: catalog with metadata sync, novels-sync crawler, anti-Cloudflare request pacer with Retry-After handling, self-healing Cloudflare+Anubis bypass, widened retry backoff (16s–256s), 10-minute batch metadata sync.
- **Dashboard**: live pipeline metrics replacing demo widgets, aggregated stats endpoint.
- **Block-centric pipeline**: block-scoped translation with per-block chunks/clean text/audios, parallel chunk view, unified pipeline architecture, Edge-TTS audio synthesis, pipeline tracing/resume, start button on Traducción, retry budgets that only consume on genuine failures (manual runs bypass them).
- **Real-time log viewer**: in-app SSE log stream (Visor de Logs) with no external tools, plus a class-filter combo-box built from the classes present in the stream.
- **Glossary system**: series glossary with LLM extraction for consistent, non-literal translations, book-scoped terms deleted when a book is removed, curation UI by scope.
- **Maintenance**: NVIDIA SDK network-error retries, npm audit fixes, Angular 21.2.24 upgrade, lockfile normalization.
