# Google Markdown Style Guide Summary

This document summarizes key rules and best practices from the Google Markdown Style Guide.

## 1. General Principles
-   **Readability:** Ensure Markdown source is readable and portable.
-   **Maintainability:** Aim for maintainable content across teams and over time.
-   **Standard Syntax:** Prefer standard Markdown syntax over HTML.

## 2. Headings
-   **ATX-style:** Use ATX-style headings (e.g., `# Heading`).
-   **Uniqueness:** Headings should have unique, complete names and spacing.
-   **H1 Limit:** Only use a single H1 heading per document.

## 3. Lists
-   **Lazy Numbering:** For long ordered lists, use lazy numbering (e.g., `1. Item 1`, `1. Item 2`).
-   **Nested Lists:** Pay attention to nested list spacing for clarity.

## 4. Code
-   **Fenced Code Blocks:** Use fenced code blocks (```````) instead of indented code blocks. Specify language where possible.
-   **Code Spans:** Use code spans (`` ` ``) for inline code.

## 5. Links
-   **Explicit Paths:** Prefer explicit paths for internal links.
-   **Informative Titles:** Use informative link titles.
-   **Reference Links:** Use reference links for long URLs to improve readability.

## 6. Formatting
-   **Bold:** Use double asterisks (`**`) for bold.
-   **Italic:** Use underscores (`_`) for italics.

## 7. Whitespace and Line Breaks
-   **Trailing Whitespace:** Avoid trailing whitespace.
-   **Blank Lines:** Separate Markdown elements with exactly one blank line.

## 8. Tables
-   **Simplicity:** Keep tables small and simple; large or complex tables are difficult to maintain.

*Source: [Google Markdown Style Guide](https://google.github.io/styleguide/docguide.html)*
